# 模块生命周期

模块身份来自明确登记，不来自目录名猜测。每个任务必须指定实际 `<module-id>` 和 `<module-root>`，独立 Git 仓库分别核对状态。

## 新增或接入模块

```text
候选目录或仓库 URL
   --> 只读核对真实路径、Git 根和局部规则
   --> 用户确认身份与写入范围
   --> clone 或 module add
   --> 更新目录与项目资料
   --> 有源码且需要时建立或更新地图
   --> 模块局部验证
   --> 必要时跨模块集成验证
   --> doctor
```

普通 clone、下载或解压只产生候选，不代表已启用、可运行、已验证或获准修改。无 Git 目录也必须明确登记身份。

## 修改模块

- 内部实现：读取局部 AGENTS，关联当前 Req/Scenario/task，运行模块测试；不重建关系地图。
- 对外职责或接口：同时更新共享 change、接口提供方/消费方、集成 Scenario 和项目资料。
- 新增、删除、移动或关系变化：重新登记并发布一次地图，不能沿用旧 COMPLETE。

## 跨模块交接

每次交接至少记录：

- 共同 change、Requirement、Scenario 和主负责模块；
- 接口输入输出、错误、超时、兼容性和生命周期；
- 各仓库 HEAD、未提交差异或最终提交；
- 局部测试、集成结果、限制和恢复点。

多仓不是原子提交，部分完成必须分别报告。

跨模块交接按[模块任务交接模板](../../templates/task-handoff.md)记录，模板字段与上面的清单对应；未知项写明原因，不留空占位。

## 流程卡

| 项目 | 约定 |
|---|---|
| 输入 | 模块来源或候选路径、稳定 ID、局部规则、接口责任和依赖顺序 |
| 写入范围 | 经确认的模块目录、项目登记、受管项目资料和共享 change |
| 授权 | clone、本地来源、写入、建图、索引和跨模块修改分别核对 |
| 验证证据 | 来源/HEAD、目录登记、模块测试、接口契约、集成版本组合和 doctor |
| 完成状态 | 模块身份与资料一致；局部和适用集成验证分别通过，地图仅在结构变化时更新 |
