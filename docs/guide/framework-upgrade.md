# 公共工程壳升级

公共壳升级是独立变更，不与业务功能混合。目标是更新固定公共包和受管入口，保留业务事实、源码、模块规则、知识内容和活跃 change。

## 升级顺序

```text
确认目标公共壳版本
   --> 只读预览文件归属和当前项目状态
   --> 建立独立升级 change
   --> 更新 .agent-framework/ 与受管入口
   --> 清理有旧归属证明且未修改的冗余受管文件
   --> 公共检查与业务项目回归
   --> doctor
   --> 用户选择单独提交或保留
```

旧受管文件已被人工修改或归属不明时，保留文件并报告冲突，不递归清空 `.agent-framework/`。目标外文件、私有启动区和知识库不属于清理范围。

## 兼容边界

- `docs/project/` 人工正文、模块局部规则和业务源码不覆盖。
- 活跃 OpenSpec change 不同步、不归档，旧任务不因公共壳升级自动完成。
- 公共包版本变化不证明业务运行、真实宿主、设备或部署通过。
- 回滚只恢复上一版公共包和受管文件，不删除业务项目人工内容。

## 流程卡

| 项目 | 约定 |
|---|---|
| 输入 | 目标公共壳版本、当前项目指纹、旧受管记录和业务回归入口 |
| 写入范围 | `.agent-framework/`、根 AGENTS 受管区块及明确属于升级的文件 |
| 授权 | 写入、索引、hooks、外部获取和提交分别核对，升级不隐含业务实施授权 |
| 验证证据 | 升级前后人工内容指纹、公共检查、业务回归、doctor 和最终 diff |
| 完成状态 | 公共包完整且无未处理归属冲突；业务验证和提交状态分别报告 |
