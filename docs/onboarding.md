# 首次接入、升级与退出

## 首次接入

1. 区分“框架分发目录”和“目标工程”。本仓库中的 templates 是空白契约，不是工程事实。
2. 确认目标工程根、各 Git 根和未提交修改。没有 Git 也可先做文档设计，不自动初始化。
3. 检查依赖及宿主实际技能发现方式，见 [集成](integrations.md)。
4. 经授权将 templates/project 下五份文件复制到目标工程 docs/project，填写真实身份、模块、接口和约束。不得将模板未知项当作事实。
5. 公共 AGENTS 作为入口参考合并到目标工程现有 AGENTS；所有指向 templates/project 的示例链接改为目标工程 docs/project。已有规则冲突须先报告，不覆盖用户文件。
6. 按模块实际深度生成 AGENTS，并计算到工程 docs 的相对链接。生成前核对源码入口，未知事实写待确认。
7. KB 未配置时允许只读探索和规划，报告 NOT_CONFIGURED。需要建库时单独确认用途、目录和 alias；空库不是已摄入。
8. 需要行为变更时核实 OpenSpec 的真实规划根与 schema。缺 CLI/规划根时报告，仅在获授权后安装/初始化。不向上误用其他工程的规划根。
9. 保留一次接入检查记录：框架版本、技能清单、项目路径绑定、未验证环境、剩余事项。

## 使用现有工程

只引入任务需要的公共文件与技能；先输出拟修改清单。不得覆盖业务代码、已有模块 AGENTS、KB 或全局宿主配置。
独立子仓库分别确认状态。公共协作支持单仓多模块和多仓多模块，不自动启动并行 Agent。

## 升级与退出

按 CHANGELOG 和 manifest 比较目标版本，先在隔离工作区检查引用、技能兼容与本地修改。
只更新框架拥有的文件，不更新工程自行填写的 docs/project、模块 AGENTS 和 KB。
退出时先确认文件归属与用户修改，解除已授权的本地路由；本框架不提供一键删除或全局卸载脚本。
