# 公共技能与工具约束

## 1. 选择与调用

- 顶层 AGENTS.md 按阶段选择技能;实际调用前读取当前可用版本的完整 SKILL.md 及该任务要求的引用。
- 同名技能有多份时明确本次所用来源,遵守宿主指令;不要混用不同版本的步骤。项目资源文档登记本地工具位置,不在公共规则固定机器路径、数量或版本。
- 技能是工作方法,插件是能力提供方,脚本/CLI 是具体执行入口。名字相同不证明已安装、可调用或权限相同。
- 只加载本任务需要的技能和资源。缺失时报告缺口与安全替代方案;不自动安装插件、初始化索引或修改全局配置。
- 调用前确认真实参数、工作目录、输入、输出和副作用;技能示例不是已执行结果。

## 2. 协作与权限

OpenSpec 管规格与宏观任务,Superpowers 管执行方法,知识库技能管获授权的知识操作。完整交接见 [开发流程](development-workflow.md)。独立评审、并行子任务仅在宿主支持且当前指令授权时执行;否则如实说明采用自查/顺序执行。

用户当前明确任务及系统/宿主指令优先于技能默认做法。技能不得自动扩大范围、绕过审批、把文档任务变成产品实现,也不得以阶段切换要求同一授权重复确认。发生实质冲突时说明来源与影响,不静默折中。
子目录规则只细化该目录职责与命令,不能放宽上层安全边界。

## 3. 工具与工作区

- 已有 CodeGraph 时优先用于代码定位,再核对当前源码;无索引用 rg,不自动 init/sync 或添加 hook。
- 独立 Git 仓库逐一检查根、HEAD、状态和 diff;保护已有修改,不重置或混入无关工作。
- 不主动初始化 Git、push、连接真实设备、改变全局配置或执行授权范围外的删除/覆盖。
- 安装、凭据、设备、部署、发布和外部写入分别核对授权;工具可执行不等于用户已授权。
- 不把密钥、密码、API key 等秘密写入文档、日志或生成输出。知识库读写另遵守 [知识规则](knowledge-policy.md)。

## 4. 规范与事实冲突

用户决定和批准的活跃规格定义“应该怎样”;实际运行证据和当前源码证明“现在怎样”。两者不可互相冒充。代码图是索引,知识库是有来源且可能过期的经验,推理必须标明。

规格与实现不符时记录 SPEC_MISMATCH,查明原因并修复实现;只有需求确实改变且获确认才更新规格,不得静默降低验收。历史记录不覆盖当前证据,用户批准也不能把未执行验证变成 PASS。

## 5. 停止与恢复

以下情况停止依赖该条件的操作并报告,其他安全且独立的工作可继续:

- 目标、范围或完成定义无法确定,或必须扩展 change。
- 所需初始化、安装、凭据、建库、数据迁移/删除等未获授权。
- 已有修改冲突且无法安全保留。
- SPEC_MISMATCH 尚未判明处理方向。
- 结果无法绑定本次工作树/产物,或发布前无法绑定最终集成版本。
- 需要用户作出新的权限、集成或实时操作决定。
