# 公共工程壳发布

本页只面向公共工程壳维护者。普通业务项目不需要执行本页命令，也不因接入公共壳而获得发布授权。

## 发布前

1. 确认 Unreleased 变更说明覆盖实际行为、兼容性和迁移边界。
2. 更新并核对 `framework-manifest.json`，不混入无关文件。
3. 完成[验证指南](verification.md)中的适用检查和最终评审。
4. 核对发布目标、版本层级、Git 状态和用户授权。

## 自动发布

`.github/workflows/release.yml` 在每周一 02:00 UTC（北京时间 10:00）运行，也可手动选择 patch、minor 或 major。工作流先运行公共检查和测试；Unreleased 有内容时准备版本、提交清单与变更说明、打 tag 并创建 GitHub Release，没有内容则跳过。

发布工作流只维护公共工程壳，不发布业务项目，不执行真实宿主、设备或业务部署验收。

## 发布后

- 核对 tag、Release、提交和发布说明一致。
- 记录实际发布证据及未验证边界。
- 业务项目按需建立独立升级 change，遵循[框架升级指南](../guide/framework-upgrade.md)。
- 知识回流单列内容和目标，发布授权不等于知识写入授权。
