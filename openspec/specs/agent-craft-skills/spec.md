# agent-craft-skills Specification

## Purpose

为公共工程壳补上两类此前缺失的参考：给 agent 写文档的写作方法，以及模块内部接口设计的共享词汇。两者都是纯参考，不引入执行型义务、不产生第二套规格来源，也不新增运行期依赖。

## Requirements

### Requirement: 面向 agent 的文档写作参考

系统 SHALL 提供一份写作参考，覆盖 context pointer 的措辞规则、context load 与 cognitive load 两个预算、渐进披露的信息层级、co-location、leading word、negation 的失效方式，以及 no-op 指令的识别与清除。系统 SHALL 同时提供技能调用形态的说明，区分模型调用与用户调用的触发方式、上下文占用与可达范围。

#### Scenario: 编写或修改技能时读取写作参考

- **WHEN** 需要新建、修改或复用一个技能入口
- **THEN** Agent 读取写作参考，按其指针措辞、双预算和层级规则组织该技能，并能用 no-op 检查清理默认行为已覆盖的句子

#### Scenario: 修改 Agent 入口或被引用文档时读取写作参考

- **WHEN** 需要修改 AGENTS.md、CLAUDE.md 或任何由指针引用的文档
- **THEN** Agent 读取写作参考，先锐化指针措辞，再决定是否内联内容，并保持每个语义只有一处权威来源

### Requirement: 模块内部接口设计参考

系统 SHALL 提供一份接口设计参考，规定 module、interface、seam、adapter、depth、leverage、locality 的用词，明确“深度是接口的属性而非实现的属性”，并给出依赖分类、seam 纪律与“替换而非叠加”的测试策略。系统 SHALL 记录一个 adapter 意味着假想 seam、两个 adapter 才构成真实 seam 的判据。

#### Scenario: 设计或重构模块接口时读取接口设计参考

- **WHEN** 需要设计模块接口、决定 seam 位置或判断可测试性
- **THEN** Agent 读取接口设计参考，用统一词汇描述接口与 seam，并按依赖类别决定 seam 与适配器的取舍

#### Scenario: 评审模块边界时使用统一词汇

- **WHEN** 评审涉及模块内部边界的改动
- **THEN** 评审意见使用接口设计参考的术语区分模块、接口、seam 与适配器，而不是使用被该参考明确排除的近义词

### Requirement: 第三方来源与许可归属

系统 SHALL 为引入的第三方技能分组保留上游许可文件，并在第三方声明中写明来源地址、许可类型、版权归属、上游固定提交与本地适配说明。系统 SHALL 在分发清单的来源列表中登记该上游及其固定提交。

#### Scenario: 清单登记上游固定提交

- **WHEN** 检查分发清单的来源列表
- **THEN** 其中包含该上游仓库地址和固定提交标识，与第三方声明中记录的一致

#### Scenario: 第三方声明覆盖该分组

- **WHEN** 检查第三方声明
- **THEN** 其中包含该分组的来源、许可、版权归属、固定提交与本地适配说明，并说明本次引入的本地改动范围

### Requirement: 分发完整性与计数一致

系统 SHALL 将引入的技能及其全部子文档随包分发，并在分发清单中登记每一份文件的指纹。分发清单的技能计数 SHALL 与实际技能入口数一致。

#### Scenario: 技能随包分发

- **WHEN** 目标工程通过公共工程壳接入
- **THEN** 该分组下的技能入口和子文档出现在随包分发的公共包中

#### Scenario: 清单技能计数与实际入口数一致

- **WHEN** 运行分发结构检查
- **THEN** 检查通过，且清单声明的技能总数等于实际技能入口数

#### Scenario: 子文档链接在分发内可解析

- **WHEN** 检查引入技能内部的相对链接
- **THEN** 每个链接指向随包分发的文件，不指向分发根之外

### Requirement: 工作流接线为参考而非义务

系统 SHALL 把引入的两个技能作为可选用参考接入相应环节，不得因此新增必做步骤、改变既有阶段的退出条件，或引入第二套需求与完成状态来源。

#### Scenario: 阶段路由不新增必做步骤

- **WHEN** 阅读阶段路由与完整开发流程
- **THEN** 既有阶段的技能顺序和退出条件不变，引入的技能只作为该环节的可用参考被指出

#### Scenario: 既有流程不受影响

- **WHEN** 执行没有设计讨论或文档编写的普通开发任务
- **THEN** 初始化、逆向、评审、验证、集成、归档与知识回流流程与引入前一致
