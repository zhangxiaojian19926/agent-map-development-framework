# discovery-questioning Specification

## Purpose

规定设计讨论阶段的提问纪律：单线追问的默认节奏、若干互相独立的决策如何一次问完、问题与轮次的归属，以及事实查证由谁负责。目的���让设计讨论既不拖延也不混乱。

## Requirements

### Requirement: 单线追问的默认节奏

系统 SHALL 在一条线索上一次只问一个问题，并优先给出多选形式。系统 SHALL 在提问前先核对项目当前状态，并在范围过大时先要求分解而不是继续细化。

#### Scenario: 单个决策逐步澄清

- **WHEN** 一条线索上的决策需要逐步澄清
- **THEN** Agent 一次问一个问题，优先给多选，并聚焦目的、约束与成功标准

### Requirement: 互相独立的决策整轮提问

系统 SHALL 在若干开放决策互相独立时，一次问完整个前沿：给每问编号、附上推荐答案，并等待这一轮的答案后再问依赖它们的问题。系统 SHALL 把依赖其他未决答案的问题留到下一轮。

#### Scenario: 多个独立决策一次问完

- **WHEN** 存在若干互不依赖的开放决策
- **THEN** Agent 在同一轮中编号列出全部问题并各附推荐答案，而不是逐轮追问

#### Scenario: 依赖未决答案的问题推迟

- **WHEN** 某问题的答案取决于本轮尚未回答的另一问题
- **THEN** Agent 把该问题留到下一轮，不与当前轮的答案混在一起

### Requirement: 事实由 Agent 自查

系统 SHALL 要求需要环境才能回答的事实由 Agent 自行查证，SHALL NOT 把查证工作转给用户。

#### Scenario: 前沿问题需要环境事实

- **WHEN** 某问题需要读取仓库、配置或运行结果才能回答
- **THEN** Agent 自己去查并把结论带入提问，不把查证步骤交给用户
