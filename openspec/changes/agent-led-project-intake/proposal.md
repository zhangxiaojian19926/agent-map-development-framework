## Why

现有公共框架要求用户选择 init/new、准备配置和授权参数；模块 URL 只作为命令参数，缺少工程尚不存在时的持久输入。用户要求只提供一次输入并由当前 Coding Agent 接管，且明确已有工程使用“模块名称 → 仓库 URL”键值对，全新工程不要求模块仓库表。

## What Changes

- 新增宿主无关的工程启动单与通用入口；已有工程的每个键值对确定一个命名源码模块，按对应 URL 获取到其独立目录，不用 URL basename 替换用户名称。
- 输入单、解析结果和恢复状态位于目标工程外的本地启动区，不污染公共分发或 clone 目标；配置不是执行授权。
- Agent 自动选择已有远程模块、已有本地工程、全新需求或恢复路径，用户不运行命令、不填写执行 JSON、不计算指纹。
- 支持中文模块名称、稳定内部 ID、路径校验、重复键拒绝、逐模块获取结果与幂等恢复；默认分支、显式来源 ref、空仓库和认证失败分别处理。
- 当前 Coding Agent 通过通用结构化协议提交分析结果，不要求非 Codex 宿主调用 Codex CLI；保留独立 CLI 适配器和现有高级命令。
- 将基础工程接入与业务设计/实施审批分开；空工程无需仓库、分支或三份已批准产物即可完成基础准备，业务实现仍需相应规格和计划批准。
- 增加逐要求审查清单、真实自然语言验收和非 Codex 验收；未实测宿主不得标为已兼容。
- 2026-09-26 补充：初始化不能以生成模板结束；当前 Agent 须完善项目架构/协作说明和模块开发入口，提供有证据的模块地图及明确的开发交接。
- 将大工程分析改为可恢复的有界分批协议，校验完整覆盖与跨模块关系；新增模块后显式更新受影响的资料，不靠全局 watcher 自动启用。
- 保留基础 PREPARED，新增独立的资料完整性、理解覆盖和交接检查；真实非 Codex、跨宿主及最终版本验收仍为独立门禁。

## Capabilities

### New Capabilities

- `project-intake`: 初始化前输入、键值对解析、保存边界和无人工命令入口。
- `named-module-acquisition`: 按名称与 URL 获取模块，处理 ref、冲突、部分失败和恢复。
- `host-neutral-onboarding`: 当前 Agent 协议、基础准备与实施分层、兼容性与真实验收。

### Modified Capabilities

暂无已归档的主规格。现有 `add-project-bootstrap-and-maps` 仍为 24/25 任务完成，本变更建立增量接入能力并保留旧命令的审批语义；不覆盖该变更、取消其未完成项或伪称已归档。

## Impact

涉及公共入口、模板、project-bootstrap 技能、CLI/config/generation/workflow/readiness/adapters、独立的输入/获取/交接组件、测试与分发检查。逐文件清单和各文件修改方式见 design.md。

不修改原小智业务工程、不下载用户未提供的真实仓库、不安装宿主插件、不创建远程仓库、不推送、不写知识库。初始实现已本地提交为9359ceb；本轮只补充规划产物，不把新增规格当作已实现能力。任何后续兼容与易用性结论必须由真实验证支撑。
