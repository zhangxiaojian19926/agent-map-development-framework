## Purpose

为已有代码和全新需求提供可审计的工程接入入口，集中确认范围并保护已有内容，在正确规划根保存规格和生成产物，避免把模板存在或命令退出误当成可开发证明。

## ADDED Requirements

### Requirement: BOOT-01 双入口与无写预览

系统 SHALL 提供 init/new、交互和配置输入；dry-run 不创建目录、文件、锁、缓存或安装，非交互缺少必要输入必须失败。

#### Scenario: BOOT-01-INIT

- 前置条件：目标是已有工程且存在人工 AGENTS
- **WHEN** 执行 init 预览
- **THEN** 输出拟新增、保留、冲突和外部动作清单；全部文件指纹不变
- 超时：30 秒
- 环境与证据：Host：前后文件快照及输出
- 异常分类：CONFLICT / INVALID_INPUT

#### Scenario: BOOT-01-NEW

- 前置条件：仅有全新需求，尚未批准设计
- **WHEN** 执行 new
- **THEN** 停在需求和设计阶段，不创建业务代码、Git 或模块索引；确认的规划记录与实现审批区分
- 超时：30 秒（不含交互等待）
- 环境与证据：Host：目录快照和状态
- 异常分类：NEEDS_DESIGN_APPROVAL

### Requirement: BOOT-02 正确规划根和一致审批

系统 SHALL 校验 OpenSpec 实际根等于所选规划根；新工程创建前需要需求、设计和实施计划的明确确认，不以目录或布尔配置伪造审批。

#### Scenario: BOOT-02-ROOT

- 前置条件：上级目录存在其他工程的 OpenSpec
- **WHEN** 初始化本项目规格
- **THEN** 建立获授权的本地规划根或报阻塞，任何后续写入不得落到上级工程
- 超时：60 秒
- 环境与证据：Host：CLI 根返回值、写入路径审计
- 异常分类：ROOT_MISMATCH

### Requirement: BOOT-03 能力范围及文件保护

系统 MUST 将源码读取/发送、下载、Git 初始化、索引、钩子、文档写入、KB 创建分项展示；配置文件不是授权，缺失能力拒绝执行，当前只读请求优先。

#### Scenario: BOOT-03-CONSENT

- 前置条件：工程来自下载且包含自动授权字段
- **WHEN** 进入工程或非交互运行
- **THEN** 不因文件存在启用写入、Agent 网络调用或安装；仅执行当前可信上下文已确认的范围
- 超时：30 秒
- 环境与证据：Host：受控执行器调用记录
- 异常分类：CONSENT_REQUIRED

#### Scenario: BOOT-03-CHANGED

- 前置条件：计划生成后已有文件被用户修改
- **WHEN** 应用初始化计划
- **THEN** 重新核验指纹，保留用户修改并输出精确冲突，不覆盖、不强制修复
- 超时：30 秒
- 环境与证据：Host：文件内容对比
- 异常分类：CONFLICT

### Requirement: BOOT-04 幂等及断点恢复

系统 SHALL 记录每步输入指纹、输出归属和完成状态；重跑相同输入无重复配置；恢复不得删除无法确认归属或已再次修改的文件。

#### Scenario: BOOT-04-RETRY

- 前置条件：初始化中途失败且另有人工文件
- **WHEN** 运行 resume 并再次运行 init
- **THEN** 只恢复缺失步骤；人工文件保持不变；不重复安装钩子、添加条目或启动 Agent
- 超时：60 秒（外部步骤单独超时）
- 环境与证据：Host：注入失败点、操作日志、文件快照
- 异常分类：PARTIAL / CONFLICT
