# Spec Delta

## Purpose

规定本框架自己给上游技能加的改编规则必须可被执行它的 Agent 读到，并规定登记与检查方式。目的是让"框架自己的合规层"在执行时存在，而不是只存在于分发包里。

## ADDED Requirements

### Requirement: 改编层登记完整

系统 SHALL 登记每个技能有哪些本地改编层是 Agent 执行该技能时必须一并读取的。系统 SHALL 让登记与磁盘实际内容一致：登记项必须存在于对应技能目录，登记的技能名必须是真实的技能入口。系统 SHALL NOT 登记仅供按需查阅的技法参考、验证脚本或创作史。

#### Scenario: 登记项真实存在

- **WHEN** 核对某个技能的登记项
- **THEN** 每个登记的文件都在该技能目录里，且技能名对应一个真实的技能入口

#### Scenario: 只登记必读层

- **WHEN** 一个技能目录里有本地文件但它们只是按需参考
- **THEN** 这些文件不进登记，登记只列必须随技能一起读取的规则

### Requirement: 改编层可被读到

系统 SHALL 让执行某技能的 Agent 能确定地读到该技能的改编层。系统 SHALL 在 Agent 必经的技能路由文档里标出改编层文件名，而不是只在一份与执行路径无关的登记文件里。

#### Scenario: 指针在执行路径上

- **WHEN** Agent 在技能路由文档里读到某个技能
- **THEN** 同一处标出该技能要一并读取的改编层文件名

#### Scenario: 登记项被活文档提及

- **WHEN** 某个改编层文件已登记
- **THEN** 该文件名在活文档里被提及，不存在"登记了但没人知道要读"的状态

### Requirement: 改编层优先于上游

系统 SHALL 让本地改编层在与上游原文冲突时优先。系统 SHALL NOT 通过修改上游原文字节来表达本地规则。

#### Scenario: 冲突时以本地为准

- **WHEN** 本地改编层与上游原文对同一件事给出不同做法
- **THEN** 采用本地改编层，且上游原文保持字节不变

### Requirement: 移除技能不得断链

系统 SHALL 让移除一个技能入口时，仍被其他技能引用的文件继续可解析。系统 SHALL NOT 让移除技能连带删掉其他上游文件引用得到的目标。

#### Scenario: 保留被引用的参考文件

- **WHEN** 移除的技能目录里有被其他技能引用的参考文件
- **THEN** 这些文件保留在原位，引用它们的链接照常解析
