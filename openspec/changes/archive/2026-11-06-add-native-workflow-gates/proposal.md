## Why

工程壳已定义十五条工作流。不同 Coding Agent 对同一任务的分流和阶段检查仍依赖各自解释项目规则，需要一份可执行的共享契约和可复核的原生宿主验收。

## What Changes

- 登记十五条工作流并提供只读任务路由，区分主流程、条件流程、不适用与待确认；流程 ID 与教程「15 条一览」表逐行对应。
- 首批为日常开发的新行为路径校验规格、计划、批准和相关版本。支持经授权的任务记录及跨会话恢复。
- 试点 Claude Code CLI 与 Qwen Code CLI，保留原生入口，按版本、工具入口及故障行为报告覆盖；判定证据不足时要求宿主阻断，不默认放行。
- 流程判定、宿主执行与交付资格三轴分别记录，只使用已发布状态词典的状态码。本期交付资格为 `NOT_RUN`。受保护 CI 和其余工作流的新增可执行门禁由后续变更处理。

## Capabilities

### New Capabilities

- `native-workflow-gates` 提供共享路由、阶段判定、任务接续及原生宿主试点。

### Modified Capabilities

本期新增独立接口。现有初始化完成判据、业务工具契约和 OpenSpec 任务状态继续沿用。

## Impact

涉及工程壳 CLI、公共规则（教程流程 ID 对照与状态词典引用）、受管入口、私有任务记录和测试。两项试点需要单独取得真实宿主验收授权。
