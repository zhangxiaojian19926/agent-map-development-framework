## Context

参见 [提案](proposal.md) 与 [增量规格](specs/native-workflow-gates/spec.md)。现有初始化生成根入口和受管公共包。旧 doctor 继续报告初始化完整度，任务门禁及宿主覆盖使用独立结果。

## Goals / Non-Goals

**Goals**

- 国内外原生 CLI 共用工作流目录、判定和任务接续契约。
- 通过项目级原生规则与 hooks 接入，按实际工具路径观察副作用。

**Non-Goals**

- 统一启动器、额外隔离运行要求、全局宿主配置或新增模型调用。
- 本期扩展到全部十五条流程的可执行门禁、改造受保护 CI 或提供交付认证。

## Decisions

1. 在现有 CLI 增加 `flow` 和 `host` 两个新动作，各自通过 `--request` 文件读取版本化请求，不复用既有位置参数 `operation`（该参数留给 `module` 的 clone/add/sync）。`flow` 请求用 `schema=workflow-request/v1`，`host` 请求用 `schema=host-request/v1`，各带自己的 `operation` 枚举；新增操作不改版本号，改语义才升版本。路由与检查只读，记录和安装分别要求当次写入授权。现有动作及退出码保持兼容。独立新增动作可避免改变旧命令含义。
2. 目录拥有十五条流程的稳定 ID（`flow-01` 至 `flow-15`，与 `docs/guide/from-zero-to-one.md`「15 条一览」表行号一一对应）、适用范围、技能引用及条件 ID。任务上下文包含项目、模块、change、动作和事实引用。判定返回 WF-07 定义的状态码、允许的下一步和事实绑定。旧工作流 CLI 继续承担各自校验。
3. 证据核验绑定真实项目、规划根、change、批准对象指纹和作用范围。本地摘要、示例或请求字段只作为提示。首批由可核验批准来源接入适配，缺少可信来源时返回受阻。信任来源固定为系统级路径 `/etc/framework/workflow-trust.allowed_signers`，不由请求或环境变量指定；该文件与其所在目录必须对当前用户不可写，否则判定为 `NOT_VERIFIED` 并阻断——原生验收证明，放在用户 home 下的信任来源会被代理读到路径并改写，从而自签批准。调用方自填的布尔值和未绑定受信来源的内容哈希都不构成批准证据。签名私钥必须不在代理可读范围内，这一条无法机械校验，只在报告里声明。隔离样例批准只用于测试，不能被生产入口接受。
4. 私有任务记录复用现有文件事务和项目锁。锁内比较期望版本和请求标识，重复请求返回原结果，载荷不一致或版本过期拒绝。恢复重读 OpenSpec 与当前事实。工作流门禁只认受信来源签出的批准，与既有 `.framework/local-state/approvals.json` 各管各的领域、互不承认，也不因后者存在哈希就放行。
5. 宿主适配负责项目级配置预览、归属检查、事件归一化与原生结果编码。保留人工配置。hooks 同步调用确定性检查，按授权写入记录。未绑定任务或未知工具缺少事实时返回明确缺口。流程判定不为 `READY` 时请求宿主阻断该次工具调用并给出拒绝理由，不得默认放行；宿主放行仍服从其原生权限。`host` 动作提供 `preview`、`apply`、`verify` 三个操作：`preview` 只读输出文件、归属与冲突，`apply` 按当次授权写入，`verify` 只读核验已认证入口。
6. 分别记录流程判定、宿主执行与交付资格三轴，只有真实工具拒绝和副作用检查齐全时记录对应入口已阻断。文档、模拟事件和原生测试分别标记来源。三轴结果落在 `.framework/local-state/workflows/report.json`，由 `flow` 动作的 `report` 操作只读查询。本期交付资格为 `NOT_RUN`。

## Risks / Trade-offs

- 原生 hooks 可能被关闭或故障。框架侧对非 `READY` 判定一律要求阻断，但宿主原生权限仍然独立生效，故按宿主、形态、版本、配置和工具入口分别报告认证范围，不声称全局阻断。
- Shell、子任务及外部工具存在覆盖差异。独立验收每条声称受控的路径，缺覆盖时记录 `NOT_VERIFIED`。
- 检查之后工作树仍可能变化。判定绑定观察版本，恢复和交付前重新核验。原生 hooks 的保证仅覆盖实测事件。

## Migration Plan

现有业务工程按授权预览并应用所选项目级适配。旧状态保持原含义，新能力初始为未认证。撤回时仅恢复有归属且未经人工改动的受管配置。
