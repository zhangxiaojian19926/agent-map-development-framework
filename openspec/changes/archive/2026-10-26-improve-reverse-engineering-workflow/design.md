## Context

现有 `prepare_reverse()` 同时承担工具准备和单次静态记录，`record_scope()` 只接受五字段旧范围；`reverse_report()` 只检查旧记录。新增能力必须复用现有授权、锁定工具、私有状态、公开摘要和 doctor 边界，不把设备语义扩散到初始化或地图模块。详细行为见 `specs/reverse-engineering-governance/spec.md`。

## Goals / Non-Goals

**Goals:**

- 用单一版本化范围驱动多轮静态/动态观察、行为契约和可选设备试点。
- 保持旧调用兼容，同时让 v2 的状态、证据和工具选择更精确。
- 用可替换执行器和显式操作配置隔离真实设备，使默认验证完全离线。
- 让设备适配器返回统一结果，但不替具体业务选择 UI、品牌 SDK 或协议实现。

**Non-Goals:**

- 不在本变更中连接真实设备、抓取真实网络、停用真实软件包、刷写固件或部署控制台。
- 不内置任意 shell、通用 ADB 命令转发、凭据绕过、固件修改或自动批量危险操作。
- 不让 REA 输出成为源码地图证据，不改变 `initialization=COMPLETE` 的含义。
- 不引入第三方运行时依赖，不预建业务适配器或控制台目录。

## Decisions

### 1. 旧路径兼容，v2 独立校验与执行

保留旧五字段 scope 的 `record_scope()` 入口和顶层状态语义，仅修复其原文留存声明。`schema=reverse-scope/v2` 进入新校验器；缺少 `schema` 的旧输入继续走旧路径，避免把新增必填字段反向施加给旧调用方。

v2 采用严格字段白名单，核心结构为：

- `id`、`goal`、`acceptance`：稳定标识、目标和可验证结果。
- `target`：`file` 目标含路径/SHA-256/工具列表；`device` 目标含命名设备与基线指纹。
- `observations`：有序观察项，每项含独立 ID、问题、动作和证据引用。
- `evidence`：`retain` 或 `discard`，以及公开摘要策略。
- `behavior`：能力、约束、推断和观察引用，用于生成交接契约。
- 可选 `device_plan`：备份证据、基线、试点操作、恢复操作和后续命名设备。

不采用“在原五字段上不断添加可选字段”的方案，因为无法稳定地区分旧语义、校验新版本并演化状态。

### 2. 工具准备与动作执行使用同一目标选择结果

为 v2 计算最小工具集合，只检测和准备该集合；旧路径继续使用既有 bundle 语义。工具锁仍是唯一版本与完整性来源，目标请求未登记工具或当前主机不受支持时拒绝，不自动替换为全局工具。

返回结构在 v2 中分离 `toolchain_status`、`observation_status`、`runtime_validation` 和 `device_change_status`。旧 `status=READY` 仅为兼容保留，不扩展为设备成功含义。

### 3. 多轮记录采用追加式本地证据，公开摘要确定性生成

v2 状态位于 `.framework/local-state/reverse/v2/<id>/`：范围、观察 JSON、原始输出、行为契约和设备执行记录分开保存。每次观察有独立文件和原始输出哈希；重复 ID 且内容不同则冲突，不覆盖。`discard` 策略只写哈希和 `RAW_DISCARDED`。

旧 v1 原文保存到既有 `.framework/local-state/rea/` 旁的受控文件，并修正公开说明。`docs/project/reverse/<id>.md` 只由结构化状态生成，包含目标指纹、状态、限制和契约位置，不复制原文、设备秘密或私有路径。

不采用只保存哈希的方案，因为它无法复核；也不把原文放进公开 docs，因为反编译文本和抓包可能含敏感信息。

### 4. 行为契约只引用有效观察，运行状态独立

行为契约使用 `device-behavior/v1`。能力项可引用观察 ID；静态观察只能支持 `STATIC_SUPPORTED`，设备/网络观察只能支持 `DYNAMIC_OBSERVED`，无证据的判断标为 `INFERRED`。引用缺失、过期或类型不匹配时拒绝生成完成契约。

`runtime_validation` 默认 `NOT_RUN`；只有实际执行的验收记录才能改变试点验证状态。契约是设计与 OpenSpec 的输入，不新增地图证据类型。

### 5. 动态动作通过命名操作配置和参数构造器执行

在锁定配置中登记操作名称、所需授权、只读/修改类别、参数模式和超时。执行器接收 argv 数组和命名目标，不经过 shell；范围不能直接提供任意 argv。未登记操作、未知参数、重定向或目标替换均拒绝。

设备连接、只读观察和网络捕获分别检查授权。网络动作只允许命名设备和命名端点配置，不开放任意网卡或全网捕获。没有实际操作提供方时返回 `PROVIDER_MISSING`/`NOT_RUN`，不伪造观察。

不采用直接执行用户命令字符串的方案，因为它会绕过范围、审计和只读边界。

### 6. 设备试点与复制使用持久状态机

状态顺序为：

```text
PROPOSED -> RECOVERY_READY -> PILOT_APPLIED -> PILOT_VERIFIED
         -> ROLLBACK_READY -> ROLLOUT_IN_PROGRESS -> COMPLETE
```

失败进入 `FAILED` 或 `PARTIAL`，保留最后成功步骤，不自动重试。恢复执行后记录 `ROLLED_BACK`，不能同时宣称新版本已验证。

试点前核对命名设备、基线、备份文件 SHA-256、操作清单、恢复操作和 `device-change`。每个操作逐项记录，任一失败即停止该设备。复制还需 `device-rollout`、有效试点证据和相同兼容基线；逐台执行并汇总为成功、失败或部分完成。

默认只提供状态机和测试提供方，不登记真实危险操作。真实品牌/型号提供方以后经独立变更接入。

### 7. 统一适配器契约是小型标准库接口

新增设备结果规范：成功返回能力与值，失败返回 `OFFLINE`、`TIMEOUT`、`INVALID_RESPONSE`、`UNAUTHORIZED` 或 `INDETERMINATE`。提供输入校验、重复命令幂等键和结果归一化；具体适配器由业务项目实现。

不引入异步框架、后台守护进程或 UI 依赖。CI 用两个不同假协议适配器证明统一语义，用故障适配器覆盖离线和超时。

### 8. doctor 与分发只感知状态，不触发动作

`reverse_report()` 扩展检查 v2 目标及证据指纹，但不执行观察、连接设备或修复状态。普通 doctor 的 initialization、地图、索引和 runtime 语义不变。新增源码和测试按现有运行时分发白名单及清单机制登记，历史文件哈希保护继续适用。

## Risks / Trade-offs

- [原始证据含令牌或个人信息] → 仅保存在私有状态目录，公开摘要做脱敏；提供 `discard` 策略，默认测试检查泄漏。
- [用户把工具 READY 误读为设备成功] → v2 分离状态并在公开摘要同时展示 `NOT_RUN`。
- [伪造备份文件通过门禁] → 备份存在和哈希只能证明文件证据，实机可恢复性仍须单独实测验收，不能标为已验证。
- [真实设备差异导致复制失败] → 基线兼容、逐台执行、独立结果和失败停止；不跨型号自动推断。
- [兼容代码增加复杂度] → 旧路径只做必要原文修复，新逻辑限制在 v2 模块，运行完整非逆向回归。
- [操作配置被误当成设备授权] → 配置仅定义能力，仍需当次独立 grant 和范围绑定。

## Migration Plan

1. 先增加 v2 校验、证据和测试，旧 v1 测试保持有效。
2. 修正 v1 原文留存与摘要声明，保留旧记录路径和地图隔离。
3. 接入最小工具选择、行为契约、动态执行器、试点状态机和适配器契约。
4. 更新技能、工具说明、目录指南和框架清单，运行全部离线回归与严格规格校验。
5. 实机提供方和真实设备验证不随本变更自动启用；以后新增时保持默认 `NOT_RUN`。
6. 若需回退，停用 v2 入口并保留既有本地证据；不得删除旧记录或用旧摘要覆盖新证据。旧 v1 路径始终可独立使用。
