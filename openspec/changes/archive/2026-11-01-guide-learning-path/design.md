# Design

## Context

动机见 [proposal.md](proposal.md)。这里记约束实现的判断。

现有指南 1391 行，覆盖 15 条工作流、37 个编号小节、7 个组合场景和 8 个故障排查条目，结构完整。缺的是**教学层**：全景、机制模型、状态词典、连续走查、自检。

`docs/guide/` 下已有五篇专题（`daily-development`、`framework-upgrade`、`module-lifecycle`、`project-layout`、`testing-and-delivery`），都是"怎么做某件事"的卡片，没有一篇讲共享机制模型。`project-layout.md` 的"状态不能混用"讲的是**四类信息**的归属，与**状态码**词典是两回事。

## Goals / Non-Goals

**Goals:**

- 读者读完指南能说出 15 条工作流的关系、主线是什么、状态码意味着什么、自己是否掌握。
- 指南声明的状态码不会与代码脱节。

**Non-Goals:**

- 不重写已有工作流内容。15 条的提示词、产物、完成判断都保持原样。
- 不重做 PDF。图稿只存在于 PDF 二进制内，仓库无源。
- 不给每条工作流补统一字段。现有各条已具备作用、流程、产物、提示词、完成判断与边界，逐条补字段是低价值改动。

## Decisions

**决策一：模型速查独立成文件，不塞进主指南。**

教程是**通读型**材料，状态词典是**查阅型**材料——读者读词典时不是在"读"，是在"查"。混进一份 1600 行的文件，两者互相拖累：教程被查阅内容打断，词典被埋在不相关章节中间。

`docs/guide/` 本来就是多文件的组织方式，新增一篇符合惯例，也让它能单独被其他文档引用。

**决策二：状态词典每条都带"下一步"，不只给含义。**

状态是**事实的分类**，不是完成度的打分。看到 `STALE` 的人真正需要知道的是"现在该做什么"，不是"它代表陈旧"。所以词典的每一行是三列：状态、含义、下一步。指南 §4 原来那张 13 行速查表只有两列，因此保留它作为正文速查，同时指向完整词典。

**决策三：状态码从代码提取，不手写。**

写词典时先用脚本把 `tools/` 与 `skill/` 下的状态字面量全抽出来，逐个核对 44 个候选 token 是否真实存在，再据此成文。**没有凭印象写下的状态码。**

**决策四：加机器检查兜住漂移。**

词典和正文里的状态码由 `tools/check-framework` 校验：每个 token 必须在随包发布的代码里存在。方向是"文档 → 代码"——文档写出代码从不会产生的状态是最容易犯也最难自查的错误。

反过来（代码产生了词典没收录的状态）不做强制：那会要求穷举代码里全部字符串字面量，噪音远大于收益。词典的完备性靠新状态被引入时同步补文档。

受检的状态表用 HTML 注释显式标记。**未标记的状态表按未受检报出**，而不是静默跳过——否则加新文件时漏标记就等于没检查。

**决策五：PDF 保留，标注版本边界，不重做。**

`docs/guide/from-zero-to-one.pdf` 是 38 页、16 张矢量流程图的图文版，绑定 2026-10-30 的提交 `b952cb3`。那 16 张图**只存在于 PDF 二进制里**，仓库中没有图稿源：主指南 88 个代码块全是 `text`，没有任何 SVG 或 mermaid。

仓库里可用 `pandoc` 与 Chrome 重新生成 PDF，但产物会退化成 38 页纯文字、丢掉全部流程图——那是降级不是更新。所以保留 PDF，在指南顶部写明它是哪个版本的图文版、图稿不在仓库、内容以 Markdown 为准。

**决策六：主线走查用一个具体项目，不用抽象流程。**

抽象流程（"接入 → 开发 → 交付"）读者记不住，因为它和 §0 那行流程图信息重复。选一个具体项目（设备告警助手）走一遍，每步给出**进入状态**、**做什么**、**状态怎么变**、**留下什么**、**注意什么**五项，读者才看得到状态怎么一步步移动、以及每一步哪里容易被误读成"已经完成"。

## Risks / Trade-offs

- **主指南变长**（1391 → 1636 行）→ 顶部三步读法给出明确路径，读者不必通读；模型速查独立成文件后，指南的重读压力主要落在新增的两个新部分上。
- **分部重编号可能破坏外部引用** → 全仓搜索确认没有任何文档引用主指南的具体章节号，引用都是文件级的。
- **状态词典可能随代码演进过时** → 机器检查守住"文档声明的必须真实存在"这一侧；另一侧靠新增状态时同步补文档。
- **自检清单可能变成形式主义** → 每题都指向具体回看位置，并写明自检不能替代独立评审与真实环境证据。

## Migration Plan

不涉及迁移。运行时载荷新增一个 Markdown 文件，其余为原地修改。
