## Purpose

将证据完整且状态为 READY 的发布候选转换为具体渠道可复核的本地产物，同时保持资产来源、隐私、人工发布审批和真实外部执行之间的明确边界。

## ADDED Requirements

### Requirement: 显式渠道适配与离线边界

系统 SHALL 仅在用户提供有效渠道适配请求时生成本地产物，并 SHALL 拒绝与其他业务动作混用。系统 MUST NOT 在该能力中访问网络、调用渠道 API、执行 Git 操作、上传、打 tag、创建 Release 或部署。

#### Scenario: 接收渠道适配请求

- **WHEN** 用户为 READY 候选提交结构完整的渠道请求并明确允许写入
- **THEN** 系统仅离线生成该渠道的本地资产、说明、清单、报告和回执

#### Scenario: 默认流程不受影响

- **WHEN** 用户未显式运行渠道适配
- **THEN** 初始化、普通开发、逆向、研究、候选和公共壳发布不增加渠道文件、网络或授权要求

### Requirement: READY 候选与来源新鲜度

系统 SHALL 将渠道请求绑定到唯一候选 ID、候选请求及其哈希、候选报告及其哈希，并 SHALL 核验候选回执、报告、请求和所选当前资产保持一致。候选状态不是 READY、来源不匹配或当前资产已变化时，系统 MUST 拒绝适配。

#### Scenario: 有效 READY 候选

- **WHEN** 候选整体状态为 READY，声明的请求和报告哈希匹配，且所选资产仍与候选清单一致
- **THEN** 系统接受该候选作为唯一资产与公开说明来源

#### Scenario: 非 READY 或过期候选

- **WHEN** 候选为 GAPS_OPEN 或 FAILED，候选资料被篡改，或任一当前资产哈希已变化
- **THEN** 系统在写入前拒绝适配并保留既有渠道产物

### Requirement: 显式资产选择与公开安全

系统 SHALL 仅适配请求逐项选择且属于候选清单的资产，记录来源路径、公开文件名、大小和 SHA-256。系统 SHALL 拒绝未选择资产被隐式加入、渠道外文件、符号链接、路径逃逸、私有路径、重复来源及重复或大小写冲突的公开文件名。

#### Scenario: 合法资产映射

- **WHEN** 请求将一个或多个候选资产映射为受限且不冲突的公开文件名
- **THEN** 系统按原字节复制这些资产并在渠道清单中绑定其实际元数据

#### Scenario: 不安全或隐式资产

- **WHEN** 请求引用候选之外的文件、私有资料、不安全路径或冲突名称
- **THEN** 系统在写入前拒绝请求，不产生部分渠道目录或报告

### Requirement: GitHub Release 渠道契约

系统 SHALL 首版支持 `github-release` 渠道，并要求公开 `owner/repo`、tag、标题以及布尔 draft、prerelease 属性。系统 SHALL 拒绝未知渠道、凭据、URL 形式仓库、非法标签或不安全公开文本，不得把适配结果描述为远端 Release 已存在。

#### Scenario: 有效 GitHub 目标

- **WHEN** 请求提供结构合法且不含凭据的仓库、tag、标题和发布属性
- **THEN** 系统生成对应该目标的本地 Release 说明和渠道清单

#### Scenario: 不支持渠道或非法目标

- **WHEN** 请求使用未注册渠道、含凭据目标、非法仓库或非法发布属性
- **THEN** 系统在写入前拒绝请求，不执行任何外部访问

### Requirement: 确定性渠道产物与发布状态隔离

系统 SHALL 为每个渠道请求生成固定 `dist/delivery/<request-id>/` 目录，其中仅包含所选资产、`release-notes.md` 和 `channel-manifest.json`，并生成公开报告 `docs/delivery/<request-id>-channel.md` 与私有回执。清单和报告 SHALL 绑定候选、渠道目标、资产哈希和请求哈希，并固定 `publish=NOT_RUN` 与 `execution=NOT_RUN`。

#### Scenario: 生成渠道产物

- **WHEN** 有效请求通过全部来源和资产校验
- **THEN** 系统确定性生成渠道目录、Release 说明、渠道清单、公开报告和私有回执

#### Scenario: 适配不等于发布

- **WHEN** 渠道产物成功生成
- **THEN** 报告明确本地适配已完成但远端发布未执行，不生成发布成功证据

### Requirement: 公开说明与私有资料隔离

系统 SHALL 仅从候选公开说明和渠道请求的公开字段生成 Release 说明及报告，MUST NOT 读取或复制验证附件正文、私有回执正文、逆向原始证据或私有产品观察到公开产物。

#### Scenario: 公开说明渲染

- **WHEN** 候选包含公开摘要、变化和已知限制
- **THEN** 系统仅使用这些公开字段和渠道公开目标形成 Release 说明

#### Scenario: 私有内容混入

- **WHEN** 请求试图把私有文件、附件或私有自由文本作为渠道输入
- **THEN** 系统拒绝该请求且既有公开产物保持不变

### Requirement: 预检、幂等、冲突与完整恢复

系统 SHALL 支持不写文件的 dry-run，并为同一渠道请求识别重复输入、合法更新和人工冲突。渠道目录、公开报告或私有回执任一缺失、被修改或来源不匹配时 SHALL 形成冲突；任一提交阶段失败时 SHALL 恢复全部旧产物或清理本能力新产物。

#### Scenario: 预检和重复执行

- **WHEN** 用户执行 dry-run 或以完全相同输入重复适配
- **THEN** dry-run 不创建文件，重复执行返回 `UNCHANGED` 且全部产物保持一致

#### Scenario: 合法更新与人工冲突

- **WHEN** 同一请求 ID 获得合法变化，或既有任一产物被人工修改
- **THEN** 合法变化返回 `UPDATED`，人工变化被保留并以冲突拒绝覆盖

#### Scenario: 分阶段写入失败

- **WHEN** 渠道目录、公开报告或私有回执的任一提交阶段失败
- **THEN** 系统恢复先前完整产物或清理本次新产物，不留下看似有效的部分适配状态

### Requirement: 静态渠道扩展边界

系统 SHALL 通过受审的静态渠道注册表选择适配器，MUST NOT 根据请求动态导入、安装或执行第三方适配代码。新增渠道或真实发布执行 SHALL 通过后续独立规格与授权实现。

#### Scenario: 未注册渠道

- **WHEN** 请求指定静态注册表中不存在的渠道
- **THEN** 系统返回受控不支持错误且不创建产物
