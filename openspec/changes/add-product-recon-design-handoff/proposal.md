## Why

第一阶段已形成证据绑定的 `product-recon/v1` 私有产品观察视图，但 Agent 仍缺少明确的读取、时效核验、设计草案交接和 OpenSpec 进入方式。若直接把观察视图当作已批准需求，会混淆产品事实、推断、设计决定与实现验证，也可能把私有内容复制进公开文档。

## What Changes

- 增加显式、只读的产品观察设计交接能力，将指定逆向 ID 的有效产品视图整理为 `docs/project/design-input.md` 的待确认草案，并生成固定结构的交接元数据。
- 交接前校验产品视图结构、计划/行为契约绑定和证据新鲜度；过期、篡改、缺文件或不兼容版本明确失败，不生成或覆盖设计草案。
- 草案保留稳定 S/F/C/E ID、观察与未观察范围、置信度、排除分类及来源指纹；私有自由文本、原始证据和秘密不进入公开草案。
- 将交接接入普通 DISCOVERY → SPEC → PLAN → IMPLEMENT → VERIFY 流程，并补充面向使用者的目录与操作指南；不自动创建或批准 OpenSpec 需求、不写业务代码、不运行真实目标。
- 重复交接保持幂等；同来源更新显式替换本能力所有的草案，来源冲突或人工修改时保留现状并要求重新核对。

## Capabilities

### New Capabilities

- `product-recon-design-handoff`: 将经过校验的产品观察视图安全、可复核地交接为待确认设计草案和普通开发流程输入。

### Modified Capabilities

无；本变更不修改既有逆向请求、观察、产品视图或 OpenSpec 审批语义。

## Impact

- 影响自动逆向的可选设计交接入口、产品观察只读校验与公开草案渲染、开发指南和离线测试。
- 新增固定设计交接状态及 `docs/project/design-input.md` 的受管输出；不引入第三方依赖、网络访问、工具安装、业务实现或自动 OpenSpec 写入。
- 保留尚未提交的 `add-completion-summaries` 工作；普通初始化、已有源码建图、旧逆向接口和未使用本能力的产品视图不受影响。
